# FitTamer

An Expo SDK 58 / React Native prototype where small movement breaks help a virtual pet grow. The demo implements the team’s prototype flows with shared in-memory state and an English mobile interface.

## Run

```bash
npm ci
npm run web
```

For a mobile simulator or compatible development client:

```bash
npm start
```

Then use Expo’s terminal options for your device. The existing project uses SDK 58; your device client must support that SDK. Web is the quickest way to present the demo, with no native build required.

## Presentation walkthrough

1. **Recharge:** Home starts with a sleepy Panda. Choose Recharge, select an activity, pause/resume the one-minute guide or use **Demo: skip timer**, then collect rewards. Home’s mood, energy, and XP update. Panda’s favorite planks grant bonus XP.
2. **Pet hunt:** Start a hunt, invite demo friends to join or watch, and use **Demo: keep walking** three times. The hint changes from cold to hot. Catch the pet, review rewards, and optionally open the share action. A hunt grants rewards once per play; Home → Demo controls → **Show hiding pet** re-arms it for another run.
3. **Collection:** Finish a quest or hunt to earn an egg. Hatch and claim it, then view and select the new companion in Pets. Three companions are included; other collection slots are placeholders. Once every companion is unlocked, spare eggs can be traded for XP (25 each) on the Egg screen.
4. **Party:** Create a named party, choose a logo, add friends, and hatch the shared egg. Open Weekly Goal, choose a movement type and 30–300 shared minutes, and save. Demo time controls advance contributions. A party only counts minutes earned after it was created, so leaving and re-creating a party starts from zero. Complete the goal and evolve Ember from the recap to collect the one-time XP reward.
5. **Reset:** Home → Demo controls → Reset all demo progress. You can also switch the Home pet between sleepy, happy, and hiding states.

## Pages and code

- `src/app/`: Home, Recharge, Quests, Hunt, Pets, Egg, Party, Weekly Goal. The old `/explore` URL redirects to Quests. `_layout.tsx` mounts the header and tab bar once (`Shell`), so tab switches don’t rebuild them.
- `src/components/demo/`: shared mobile layout, cards, buttons, animated progress bars, sheets, friend picker, floating pet animation (honours the OS reduce-motion setting), and illustrated campus map.
- `src/state/demo.tsx`: session state and reward transitions shared across routes.
- `scripts/test-demo.cjs`: reducer tests for rewards, collection, eggs, party minutes/evolution, mood and the demo controls.

## Demo boundaries

Movement, location, quest completion, friends, invites, and cheers are simulated and labeled in the interface. The map is an illustration, not a GPS map. Native sharing opens the system share sheet; web provides a copyable summary. No invitations or messages are sent automatically.

Progress lasts for the current app session; reload/restart resets it. Daily activity and quest rerolls are enforced within that session. The demo has no authentication, backend, health sensor integration, background tracking, or persistent storage. Party contributions from friends are sample records. New party membership and goals operate locally.

## Validation

```bash
npm run lint
npm run typecheck
npm run test:demo
npx expo export --platform web
```

CI (`.github/workflows/ci.yml`) runs lint, typecheck, the demo tests and a web export on every push and pull request.

Typed route declarations are generated by Expo. If a fresh checkout reports unknown route paths, run `npm start` once before typechecking.
